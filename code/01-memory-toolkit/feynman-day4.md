# 费曼讲解 · 一个 C 程序的内存里都住着什么

> zl ｜ W1-D4 ｜ 听众假设：零基础
> 规矩：比喻开头，实测证据跟上；术语出现必须当场解释。

## 开场：内存是一栋楼，地址是门牌号

程序运行时的一切——指令、文字、变量——都住在内存这栋大楼里。今天带你从下往上逛一圈：这栋楼里都住着谁。

第一个房间住着栈，栈就像是大楼高层的临时公寓，规则是**自动租住，自动退房**。
每当进入一个函数，就相当于在楼下加盖一间新房；函数执行结束，这间房间就立刻清空回收。而且公寓只允许从最顶端存取物品，也就是后进先出。
## 1. 栈：自动租住，自动退房

“自动租住自动退房” + “楼下加盖新房，实测每次减 64”
我们连跑 4 层递归，门牌号每次刚好减 64——CFFC20 → CFFBE0 → CFFBA0 → CFFB60。数字会变（ASLR），但“逐层变小”永远不变。
## 2. 堆：手动申请的商铺

堆相当于大楼里一片商业街商铺，**商铺不能自动分配，必须手动申请，用完也必须主动归还**。
拿到的商铺门牌号，就是我们所说的**指针**。如果申请了商铺，用完却忘记归还，就会一直被占用，也就是**内存泄漏**。堆的空间很大，但读写会比栈稍慢一点。

heap new#0 ~ new#4 五个乱序地址 + heap strictly increasing? = NO    五个地址都是乱序     实测结果并不固定：有时 NO，有时 YES——分配器不承诺任何顺序，能依赖的只有‘不保证’。

## 3. 全局区：两间格子

全局区拆成两块，一间叫`.data`区，一间叫`.bss`区。

- `.data`区：开工时就摆好物品，存放**已经赋好初始值**的全局变量。
- `.bss`区：是空房间，程序启动时系统自动把里面全部填零，存放**没有初始化**的全局变量。

举个例子：全局的字符串指针存放在`.data`；未初始化的全局计数器，就放在`.bss`。
## 4. 常量区：只读

常量区存放用双引号写出来的文字常量。
这片房间有硬性规定：**只允许读，不允许改写**，一旦强行修改里面的内容，程序就直接崩溃。
## 5. 代码区：大楼最底层

大楼最底层是代码区。这里放着编译好的机器指令，也就是我们写的 C 代码翻译成机器能读懂的命令，同样是只读的。CPU 会逐条读取这里的指令，然后执行

## 结尾：这栋楼每晚都换门牌（ASLR）

最后回到开头的伏笔：操作系统每次启动程序，都会把整栋大楼所有房间的门牌号整体重新随机更换一遍，用来防止黑客利用固定地址攻击程序。
但是，各个房间之间的相对距离永远不变，也就是我们做差值验证看到的 “整体搬迁” 现象。
## 补充：教科书的图 vs 我的实测

教科书画的‘代码在最底、栈在最高’是经典模型；我们实测 Windows 上模块区反而在最高位——位置由 ASLR 决定
① 教科书画"代码在最底、栈在最高"——那是经典/Linux 模型
② 我们实测：栈 ≈150GB、堆 ≈266GB、模块区 ≈140TB——Windows 上模块区在最高位
③ 结论：区域位置由 ASLR 决定，我不记结论，只记"模块区内部顺序固定"
## sizeof 家族实测（W2）
成员间垫字节，是为了结构体内部每个成员对齐；尾部凑整，是为了结构体数组里每个元素都对齐。两处 padding，同一个目的：让对齐承诺在任何摆放方式下都成立。
| 类型/结构体 | 手算 | 实测 |
|---|---|---|
| struct S (char,int,char) | 12 | 12 |
| struct Inner (char,int) | 8 | 8 |
| struct Outer (char,Inner,char) | 16 | 16 |
| struct T (char,double,int[3]) | 32 | 32 |
| int* / char* / void* | 8 | 8 |

手算与实测全部一致。padding 不是浪费，是 CPU 对齐读取的代价。

## bss 为什么不存 0（空洞 #3 已补）

exe 只记录 bss 区的位置和大小，不存储那些 0——100 万个未初始化全局变量只多占几字节文件；加载时由操作系统统一把整块内存清零。
## 虚函数表实证（W3）
vptr 住对象开头：父类指针拿到首地址就能找到子类的虚表（多态的根基）。
vtable 住只读区：编译期常量，OS 只读保护防篡改。
跨运行对比：vtable 低 16 位（13F0/13D0）恒定，只有基址漂移——整体搬迁再实证。

前面我们逛完了这栋楼的房间布局。现在换个角度问一个问题：C++ 的对象在这栋楼里怎么住？ 答案从每个带虚函数的对象开头那 8 个字节说起。
- 对象开头 8 字节是 vptr，实测指向模块区 .rdata（只读）
- 虚表内容 = 函数指针数组，按声明顺序排列：实测 vtable[0]=speak(…13F0)、vtable[1]=eat(…13D0)
- 表里的指针指向 .text 代码段——虚表住只读数据区，表里的地址指代码区
- 手动经 vptr 调用：fn = vtable[0]，fn(&a) 输出 woof——没有写 a.speak() 也调到了
- 实测（MSVC 19.44）：vtable[1] = eat 地址，非 nullptr——**MSVC 虚表无哨兵**；GCC 未测，不置可否
- 虚函数调用底层：取 vptr → 查虚表 → 调表项，并非编译期固定函数地址
